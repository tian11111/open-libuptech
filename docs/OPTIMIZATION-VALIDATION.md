# 第一阶段优化验证记录

日期：2026-10-30

## 范围

- P0：UART 删除 `tcdrain()`，使用有界 `TIOCOUTQ` 等待和最多三次完整发送重试；保留成功后的 1 ms 帧间隔。
- P1-A：按芯片当前 FSR 换算 MPU 数据，并随缓存样本保存比例。
- P1-B：默认 10 ms MPU 异步采样缓存；`UPTECH_MPU_CACHE_MS=0` 时使用同步读取。
- P1-C：软件互补滤波输出 `[pitch, roll, yaw]` 度。Yaw 无磁力计绝对参考，会漂移。
- ABI 保持 45 个 FUNC 导出、0 个 OBJECT 导出；不实现 DMP 或 LCD。

## 生命周期

动态卸载前，调用方必须停止所有调用库 API 的线程。析构会停止并 join MPU 采样线程，再关闭设备 fd。`pthread_atfork` 在 fork 前获取库内锁，子进程清除旧 MPU 快照并释放继承锁；模拟测试覆盖了 I²C 锁被其他线程持有时 fork 的情况。生产应用仍推荐 fork 后立即 exec，避免父子进程同时操作同一硬件总线。

## 右轮不停转反馈及修复候选（2026-10-30）

- 首次用户实测反馈：输入 1024 执行短脉冲后，右轮先猛动，再持续低速转；左轮停下。当时电机停机验收不通过，前述 mock/PTY 通过不代表真实电机停转可靠。
- 源码与官方 ARM32 二进制比对确认，右轮 `-1023` 使用方向位 `0x400`，零速编码不带方向位；未发现 GUI 在定时器后另发低速命令。
- 确认的实现缺陷：旧等待在 `TIOCOUTQ==0` 后仅等 20 µs；软件队列可在整帧仍位于 FIFO 时归零。新增模拟时钟/GPIO 测试在旧实现下失败，修复后通过。该缺陷可能造成真实帧截断，但尚无现场抓包证明它就是本次右轮故障的唯一原因。
- 修复后队列清空再等完整帧线上时间加 20 µs；9 字节帧保持至少 110 µs。仍有三次有界发送重试和成功后的 1 ms 帧间隔。没有把重复发送零速或改方向位作为补丁。
- GUI 对每轮分别记录 result/errno；即使左轮调用抛异常仍尝试右轮零速。失败显示红色警告并重新锁定脉冲；成功仅表示“零速帧已发送；无停转反馈”，不宣称物理停转。
- Pi 隔离目录构建无警告，`make test` 10 项通过（风扇5、MPU mock1、UART mock1、Qt fake3），ABI 45 项不变。Qt fake 覆盖右轮/双轮1024脉冲、两轮归零、任一轮返回EIO或抛异常；停机成功/失败截图已目视检查。本轮没有打开真实 UART 或翻转 GPIO4。
- 新候选单独位于 `~/openlib-stopfix-20261030`，库 SHA-256 为 `e495984693391a121451cfa45d8769f78c67343cd0894f2e8eb645eec19c5c10`。`~/openlib-work`、`~/libuptech64` 和仓库旧 `.so` 均未替换；正在运行的 GUI 未重启。
